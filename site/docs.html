Overview

local-sec is a local-first supply-chain guard for developer installs. For supported artifact paths, it stages the package bytes, scans them, checks advisories, then returns one of three lanes:

trusted risky blocked

Project lockfile installs use an audited rewrite without artifact staging; one-shot paths can defer staging for review or be blocked. It runs as a single binary on your machine. There is no SaaS agent and no product telemetry. Optional advisory lookups send only package name and version tuples.

Install

1. Download the binary

Get a release for your platform and verify it against checksums.txt. Archives ship for macOS (arm64/amd64), Linux (amd64/arm64), and Windows (amd64).

2. Put lsec on your PATH

Extract the archive and place the lsec binary somewhere on your PATH.

3. Install shims

$ lsec install-shims

lsec install-shims writes shims and tells you which directory to add before package-manager directories in your PATH. Make that PATH change yourself, then confirm with:

$ lsec doctor

After that, use supported npm, pip, uv, curl, and related commands as usual.

npmnpxpippip3 uvuvxpipxcurlwget

Commands

Core day-to-day commands:

lsec guard npm install <package> lsec preflight npm install <package> lsec install-shims lsec doctor lsec status lsec inbox [limit] lsec approvals list lsec scan --profile project --root . lsec evidence npm install <package>

For supported staged paths, guard stages, scans, advisory-checks, then allows, prompts, or blocks. Lockfile installs use an audited rewrite instead; one-shot paths can defer staging for review or be blocked. preflight reports the applicable path without completing a real install.

Useful review commands:

lsec history [limit] lsec packages [limit] lsec show <run_id> lsec inbox show <run_id> lsec approvals suggest <run_id> lsec approvals add <ecosystem> <name> <version> <sha256>

Verdicts

Trusted

Mature package, clean staged scan, clean advisories. The install proceeds as requested.

Risky

Held for local review — too-new packages, install scripts, direct downloads, first-seen maintainers, and similar flags.

Blocked

Hard stop: known malware, curl | sh, plain HTTP, unresolved identity, or advisory refresh failure without a cache.

No silent swaps

local-sec never installs a different version behind your back. Ambiguity blocks; it does not allow.

Pipeline

Supported staged installs walk this path:

preflight → stage → scan → advisory → verdict

Privacy & safety

  • Fail-closed. If identity cannot be resolved or an advisory refresh fails with no fresh cache, the run blocks.
  • No telemetry. local-sec does not phone home about your machine or projects.
  • Metadata-first. Project inventory reads allowlisted metadata (lockfiles, package metadata, receipts) — not source trees, .env files, SSH keys, or shell history.
  • Redacted evidence. Bundles scrub secrets and host paths before any handoff leaves the machine.
  • Advisory lookups. Optional network checks send only normalized ecosystem / name / version tuples.

Scanner

lsec scan is a privacy-conscious metadata inventory — not a full-disk source scanner. It can inventory lockfiles, installed package metadata, Homebrew receipts, editor extension manifests, and sanitized MCP config.

$ lsec scan --profile project --root . $ lsec scan --profile baseline --network off $ lsec scan --profile deep --network advisories

With --network advisories, it can query OSV and optionally use tools already on your machine such as osv-scanner, pip-audit, or grype when present. Missing optional tools are reported; they do not weaken core policy.

Approvals

Persistent approvals are exact: package + version + SHA-256. Different bytes never inherit an old approval.

$ lsec approvals suggest <run_id> $ lsec approvals add npm express 4.19.2 <64-hex-sha256> $ lsec approvals list $ lsec approvals revoke npm express 4.19.2

Risky runs land in a local inbox for review:

$ lsec inbox $ lsec inbox show <run_id> $ lsec inbox approve-once <run_id> $ lsec inbox deny <run_id>
